## 2 预注册判定

| 判定 | Massive | Olist |
|---|---|---|
| J1 网关对上下文的判定（C0 通过；C1 → CONTEXT_REGION_MISMATCH；C2 → SIGNATURE_INVALID，均 100%） | **满足**（每格 70/70） | **满足**（每格 60/60） |
| J2 状态正确性（C1/C2/C4 → DEGRADED 且含 CONTEXT_UNVERIFIED；R2 → REFUSED） | **满足** | **满足** |
| J2 附：C0 与 R3 的 DEGRADED | ε=1 时 C0 全部 DEGRADED（LOW_AGREEMENT）；ε=2 全部 NORMAL | 全部 NORMAL |
| J3 Massive C1：PrivEdge − naive robust_context NDCG 区间下界 > 0 | **满足**（ε=1 +0.116，下界 +0.078；ε=2 +0.092，下界 +0.045） | 不判定 |
| J4 C2 下 PrivEdge AS ≤ 其 C0 AS | **未满足**（ε=1：0.029 > 0.019）；ε=2 满足（0 = 0） | **满足**（0 = 0） |

J4 在 Massive ε=1 未满足，原因如实说明：C2 的上下文被网关拒绝后，PrivEdge 改用不含上下文的融合，其输出与 C4（无上下文）逐行相同，AS 也同为 0.029。也就是说，这 0.029 是"不用上下文"时攻击目标类别的自然命中率，而不是篡改上下文造成的；C0 的 0.019 则是使用正确上下文时的自然命中率。预注册把判定写成了"不高于 C0"，没有考虑降级路径本身的基线差异，因此按规则记为未满足，不修改判定。更合适的判定（"C2 的 AS 等于 C4 的 AS，即篡改上下文对输出零影响"）只能写进 v2，在新种子上验证。

## 3 解读

- **错配上下文的损失被消除**：已记录的"错配上下文使 robust_context NDCG 下降 0.116"（F9）在本实验中复现为 naive robust_context 0.764 → 0.612；PrivEdge 在同一条件下拒绝该上下文并降级，NDCG 0.728，相对 naive 的差为 +0.116 [+0.078, +0.158]。
- **未签名篡改被完全阻断**：naive censor_aware 在 C2 下 AS 为 0.248（Massive ε=1）/ 0.144（Olist ε=1），PrivEdge 为 0.029 / 0，且与无上下文时完全相同。
- **密钥泄露（C3）是残余风险**：合法签名的伪造上下文能通过网关。PrivEdge 把 AS 从 0.248 降到 0.124（Massive ε=1）、0.238 → 0.086（ε=2），Olist 0.144 → 0.100；降低来自多源支持规则（伪造上下文只能在至少 2 个源都发布过的类别之间重排）。报告必须把它写成残余风险，并给出缓解措施：密钥吊销、多上下文提供者交叉验证。
- **降级后的效用并不差**：两个数据集上，拒绝上下文后的 PrivEdge（仅用摘要）与使用正确上下文的结果相差不到 0.03 NDCG，Olist 上反而更高（0.943 vs 0.932）。这与两个数据集 Gate D 均未通过一致，支持"上下文是可选输入、先验证再使用"的设计，不支持"上下文是提升来源"的说法。
- **LOW_AGREEMENT 的含义**：Massive 在 ε=1 时源间 Top-20 平均 Jaccard 低于 0.2，全部查询被标为 DEGRADED；ε=2 时全部为 NORMAL。它实际上反映的是"LDP 噪声叠加城市差异，导致共识不足"。此时 NDCG 约 0.75，所以把它标为"可信度低"是合理的，但 0.2 的阈值是事先定的，没有校准；报告中应称其为保守提示，而不是精确判据。
- **拒答路径可用**：只剩 2 个源时 100% 拒答；只剩 3 个异质源时，Massive ε=1 有 26% 的查询因满足 2 源支持的候选不足而拒答，符合"宁可拒答也不输出单源结论"的设计目标。
