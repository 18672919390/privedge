# E31 整合程序运行复查（工程验证）

本方案在本轮运行检查及修复前记录。目标是核对 E30 整合候选的真实启动与用户操作，不生成新的算法效用结论。

- 保留 E30 ZIP，不覆盖旧 runs、原始数据或研究代码；仅解压到新的临时目录，账本使用进程内存。先核对包清单，执行随包自检，再实际启动 HTTP/WebSocket 服务。
- 用现有本机 Edge 无头浏览器操作五个页面；三数据各运行一次冷启动预测和一次攻击；TRD 执行完整攻击巡检，检查结果归属、完整日志和账本副本篡改拒答。浏览器操作使用页面现有默认参数，固定种子只用于后端合法输入回归（seed=1、epsilon=2、m=40、users=1000）。不按结果挑选参数、不调优。
- 检查合并边界：首次数据集加载失败后能否恢复；数据集与页面切换；运行中断；已有和A8证据独立加载。故障注入与真实操作分开记录。
- 对可重复的新缺陷先保留失败证据，再最小修复，新增必要回归并运行完整测试、类型检查和构建；保留旧版可重现输入的决策与评价比较。不重复修复10月9/10日已经关闭的问题。
- 修复后冻结新候选，执行随包完整性、自检及测试；最终核对257项保护文件和旧证据指纹。旧E30与新候选分开标识，不重用旧包哈希。
- 通过标准：指定功能均能完成且有终态，无未处理浏览器异常或HTTP 500；篡改演练拒答且原账本完整；构建及完整测试通过。失败也保留记录。实际第二电脑、Linux/Mac当前整合版和完整原始数据重建不在本轮已验证范围内。
