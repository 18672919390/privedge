# 发布协议形式化验证（ProVerif 2.05）结果

- 模型：`formal/privedge_release.pv`；运行器：`privedge/experiments/formal_v1.py`（自动生成负对照并逐一验证）
- 工具：ProVerif 2.05 官方 Windows 二进制（`tools/proverif/proverif2.05/proverif.exe`）
- 运行：`runs/formal_v1/formal_v1-20260929T145230Z-a095ce/`（含主模型、4 个负对照 .pv 与 `results.json`）；全部验证约 2 秒

## 模型范围
- **攻击者**：Dolev-Yao 网络攻击者，可窃听、篡改、重放、伪造任何消息。数据源 T 的"数据源角色"私钥被泄露（Compromised 事件）。
- **参与方**：诚实数据源 A、B、T，以及 T 的上下文机构。账本服务只登记签名能在注册表中对上 (数据源, 角色) 的信封；目标网关检查注册表角色、签名、窗口，以及账本中的摘要值。
- **与代码的对应**：签名覆盖窗口号，对应 `envelope.body()`；角色绑定对应 `keys.check_signed`；账本验签对应 `Ledger(registry=...)`；账本核对对应 `gateway._check_release`。
- **不在模型内**：隐私预算的数值累加；同源多摘要拒收（EQUIVOCATION，由代码和单元测试保证）；统计防御（由定理 1、2 和实验保证）。

## 主模型结果

| 编号 | 性质 | 结果 |
|---|---|---|
| Q1 | 认证、完整性、窗口绑定：网关接受的 (源, 窗口, 编号, 摘要) 一定由该源为该窗口发布，除非该源密钥泄露 | 成立 |
| Q2 | 账本绑定：网关接受的摘要一定与账本中该编号登记的摘要值一致，**对被攻破源同样成立**，所以审计方看到的就是网关实际使用的内容 | 成立 |
| Q5 | 不可代扣预算：账本中记在某源名下的条目一定由该源本人发布，除非该源密钥泄露 | 成立 |
| Q3 | 上下文真实性与角色隔离：T 的数据源密钥泄露后，仍无法让网关接受伪造的 T 区域上下文 | 成立 |
| Q4 | 数据最小化：原始用户数据对网络攻击者保密（LDP 摘要建模为单向函数，这不是差分隐私证明） | 成立 |
| S1、S2 | 可达性检查：接受事件确实可以发生，说明模型不是空转 | 可达 |

## 负对照（每个只去掉代码中的一项检查）

| 负对照 | 去掉的检查 | 被破坏的性质 | 是否符合预期 |
|---|---|---|---|
| nc1 | 窗口号不在签名内 | Q1、Q2（旧窗口摘要可以被改标成当前窗口重放） | 是 |
| nc2 | 注册表不区分密钥角色 | Q3（泄露的数据源密钥可以伪造上下文） | 是 |
| nc3 | 网关不核对账本 | Q2（被攻破源可以给网关一份、给审计方另一份） | 是 |
| nc4 | 账本登记不验签（修复前的 `ledger.append`） | Q5（任何人都能以他人名义登记，耗尽其隐私预算） | 是 |
