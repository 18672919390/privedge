# 后端功能验收方案 2026-10-13

本记录在本轮接口验证运行前建立。范围为队长负责的后端接口、可信交换流程与报告代码对应；不是A8统计实验，不生成算法优越性结论。

## 固定范围与判定

1. 读取三套已登记数据集，核对 `/api/datasets` 和 `/api/evidence`。现有证据的五组字段、运行ID及值应保持不变。
2. 使用既有回归测试的合法参数作功能检查：三套数据各取返回列表最后一个target，ε=2、top_m=40、users=1000、seed=1、attack=none。比对修复前后的决策、Top-k与离线评价；随机ID、签名、时间、窗口和耗时不作逐字比较。这是功能回归，不是新的确认性效用实验。
3. REST未知数据集、未知目标、未知攻击及非法参数应给可解释的4xx，不修改原数据或已登记运行。
4. WebSocket缺字段、越界参数、非对象JSON及非法JSON文本应返回 `kind=error`；同连接之后的合法结构、未知目标请求也应得到可解释终态，服务保持可用。不得因请求解析错误永久等待。
5. 保留现有账本副本篡改拒答、路径限制及三数据预测测试，不重新修复已关闭缺陷。模型预算边界由已有核心测试验证。
6. 源码变更后跑完整测试，记录实际通过数与失败。只为确认缺口补必要测试。

## 结果纪律

所有验证成功与失败均写入 `competition_entry/docs/v4/backend_validation/20261013/`，包括修复前后记录。旧runs、原始数据与团队原始研究代码不变。若发现新问题，先保留复现，再修复，再回归；在08第7节追加一条。本轮结果不冒充E1—E20中的统计实验，报告将其作为工程验收记录引用。
