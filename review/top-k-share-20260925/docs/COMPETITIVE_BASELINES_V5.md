# 第五步：什么才是有竞争力的基线

“有竞争力”不是把更多算法名称列在表中，而是基线必须代表一个合理、可复现的替代
假设，并且与主方法拥有相同的信息、候选集合和调参机会。`competitive_baselines.py`
新增三类可部署基线；它们尚未替换旧 G1-G8 的结果。

## 合格标准

1. **信息匹配**：只能使用已发布 Top-m、频率、方差、公开 q 和公开元数据；不得使用
   真实源目标相似度、p_T 或完整未发布频率。
2. **候选匹配**：默认只能从同一个源候选并集选择；若主方法允许公共候选扩展，所有
   基线必须同时得到该扩展。否则比较的是候选发现能力，不是融合能力。
3. **预算匹配**：同一 epsilon、用户数、服务器数、发布规模和目标 k；选源方法的
   “预算”不能被误报为隐私预算。
4. **调参匹配**：在独立开发种子上选择 alpha、trim 和频率权重；最终测试集只使用
   冻结值。不得让复杂方法调参、基线使用默认值。
5. **机制匹配**：报告协议内结果和 MIXED 结果；不能只报告最有利协议。
6. **负结果保留**：上下文误导、候选缺失、源目标迁移和边界 gap 小的场景都必须报告。
7. **成本匹配**：记录已获取发布成本、使用发布数、融合时间和内存；只减少计算不能
   写成减少通信。

## 新增基线

### 固定上下文收缩：`context_mixture`

令 a_i 为已发布频率按源取平均，q 为归一化公共上下文：

    score_i = (1-alpha) a_i + alpha q_i, alpha in {0.25,0.5,0.75}。

它代表最简单的公共先验收缩模型，使用相同源候选。若主方法只胜过它，主张应是
“删失建模/自适应机制有额外价值”，而不能只说“使用上下文有效”。

### 截尾频率：`trimmed_frequency`

对每个候选物品，取各源的已发布值；未发布按零；去掉最高和最低各一个后平均。
它代表单个异常源的稳健位置估计，不使用 q。若服务器数不足 3，禁止该基线，而不是
默默改成普通平均。

### 排名与频率：`rank_frequency`

将公开榜单的倒数对数排名与发布频率线性组合：

    score_i = sum_s [1/log2(rank_s(i)+2) + gamma*y_s,i]。

gamma 在独立开发集冻结。这是对现有 vote/average 的合理排序增强，用于检验复杂
item-level 方法是否只是利用了公开排名信息。

## 主方法必须面对的比较层次

| 层次 | 必须包括 |
|---|---|
| 无上下文 | vote、average、variance_weighted、trimmed_frequency、rank_frequency |
| 有上下文 | context_mixture、context_weighted、adaptive_context、item_context |
| 截断结构 | 不含删失项的 reported-only、旧 censor-aware、新可分析估计器 |
| 鲁棒性 | trimmed_frequency、robust_adaptive_context、恶意/陈旧/缺失源 |
| 诊断上界 | global_true_average、oracle_weighted（明确不可部署） |

`context_only` 仍保留，用来测量公共 q 自身能做到什么；它不是公平的源融合基线，
因为它可以选择源候选并集外项目，必须单独标注候选模式。

## 实验矩阵

第一阶段固定 domain=128、users=1500、servers=6、k=10、report=2、epsilon=2，
使用第四步筛选出的弱/强/误导上下文、轻/中/重迁移和小/中/大 Top-k gap，12 个
独立种子。每个种子所有方法共享同一组发布。每种方法的超参数只由另外 12 个开发
种子选择一次；最终 20 个测试种子不能回看。

主要指标：Recall、NDCG、候选覆盖上界、候选遗漏质量、L2/Linf 分布误差、运行时间、
实际发布条目和峰值内存。主要统计单位是种子；报告配对差值及区间，不把同一轮中的
多个方法当作独立样本。正式主张只预先指定“复杂方法 vs 固定上下文收缩”和“复杂方法
vs 截尾频率”两组主要比较，其余为探索性。

两项专属基线测试及完整37项测试通过。截尾在不足3源时由统一入口回退average，

`experiments/G1_competitive_baselines.py` 使用20个新种子、弱/强/误导/无上下文、
OLH/MIXED、域512、每源5000、8源、k10、Top20、epsilon2。alpha=.5、trim=1、gamma=1
在运行前固定，没有在这组输出上择优。虽文件名含formal，本轮是固定参数验证，
不是独立开发集调参后的最终确认。尚未包含第二步新估计器、完整协议扫描、方法级耗时
或峰值内存测量；这些属于后续扩展，不将预定指标冒充已完成指标。

当前混合的源平均向量没有在候选域重新归一化；q按完整域归一化。因此alpha=.5是
两个数值向量的混合系数，不代表两侧候选概率质量各占一半。后续开发阶段应公平比较
不同归一化策略，不能根据本轮测试结果挑选策略再使用同一组数据确认。

输出含原始行、均值与bootstrap区间、配对差异及全表Holm校正、配置与代码摘要，
目录为 outputs/formal_baseline_comparison。原始schema已有method字段，无需为新增
方法强行新增列。context_only独立标注候选集合；oracle仅在原始表保留。

复现（top-k目录）：`./.runtime/python/python.exe experiments/G1_competitive_baselines.py`。
同配置同代码可续跑；代码或配置变化时应使用新输出目录，不覆盖旧证据。
