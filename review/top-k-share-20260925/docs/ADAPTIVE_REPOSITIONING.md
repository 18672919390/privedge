# 第三步：重新定位自适应模块

2026-09-14。性质：研究定位、公开选源代理目标及探索性诊断。
第二步已完成模型/原型/诊断，但高概率统计保证和优于强基线的最终方法尚未完成。
第三步可以并行推进问题分解，不以第二步新原型有效为前提。

## 1. 明确自适应在优化什么

当前场景已获得所有发布结果，因此选择只发生在后处理中：读取所有 R_s 和公共 q，
决定融合时使用哪些源。不新增用户查询，不分配新的 epsilon，也不声称节省下载成本。
预算 b 是使用的源数，不是隐私预算。只有将来定义了发布前可见元数据与按需访问协议，
才可以研究选择对通信成本的保证。

这里的适应是对同一批公开发布作数据依赖决策，不是 ARBSF 的用户级自适应采样。
它也不是多轮在线学习或 bandit：没有新增反馈轮次。

如果没有实际成本限制，全源软加权是必须保留的强参照；不能为使用“自适应”而固定
丢掉一半源。选源只有在相近准确率下节省融合成本，或确有稳健性收益时才有价值。

## 2. 将三个效应拆开

1. 源单独质量：与公开 q 的一致性、估计不确定性。
2. 源集合互补性：新源补充多少尚未覆盖的公开相关项目，是否只是重复已有列表。
3. 丢弃代价：源候选减少、独立证据减少、融合权重/尺度发生变化。

原相关性除以标准误的排名只主要考虑第一项。选择后重新计算融合权重也会影响结果，
因此本轮对所有选源策略使用同一个冻结的下游融合函数及其重算规则；不把所有差异
单独归因为候选覆盖。更细的固定系数消融留待后续。

## 3. 可分析的互补性代理目标

实现：adaptive_selection.py。输入仅为 R、q、源预算、策略和随机基线的内部随机种子。
不读取真实 p_T、p_s、相似度、生成器系数或测试标签。

先冻结每个源的可靠性与排名特征：

    sigma_s = sqrt(mean_{i in L_s} published_variance_s,i)
    reliability_s = min(1, median_t(sigma_t) / max(sigma_s, 1e-12))
    a_s,i = reliability_s / log2(rank_s(i)+2)  if i in L_s; else 0。

排名从 0 开始；q 归一化。可靠性上限防止极小声明方差获得无限收益，但不构成抗攻击
保证。所有系数在整个候选源集合上算好，不能选到一半再重算，否则下面的固定集合函数
证明不再直接适用。没有 q 时本原型拒绝运行，不拿均匀向量伪造目标侧信息。

对源子集 J 定义：

    F(J) = sum_i q_i max_{s in J} a_s,i，F(empty)=0。

同一项目重复出现不会简单累加收益；若新源提供更可靠、更靠前的证据，仍可增加收益。
q_i=0 的项目对目标无贡献，体现其对公共上下文的依赖和脆弱性。
这是一种带可靠性的加权覆盖目标，不是熵、互信息或真实估计误差下降量。

## 4. 单调次模性与保证的范围

对 A subset B 及 s notin B，已有逐项最大特征满足 max_A a <= max_B a。
加入 s 的增量为 max(0,a_s,i-max_J a)，所以在 A 上的增量不小于 B 上的增量。
乘以非负 q_i 并求和，得到次模性；同时 F 非负、归一化且单调。

因此基数约束 |J|<=b 下，逐次选最大边际增益的贪心算法满足经典保证：

    F(J_greedy) >= [1-(1-1/b)^b] F(J_opt) >= (1-1/e) F(J_opt)。

证明思路：每一步，最优 b 个源的总剩余增益至少覆盖当前最优性差距，最大单步增益
至少为差距的 1/b，递推 b 步得到上式。这是标准次模最大化结论，不作为新的理论贡献。
算法复杂度为 O(b*S*d)，并列时按公开源 ID 决定，源列表输入排列不影响选择。

这个保证不涉及目标 Recall/NDCG，不意味着误差下降，也不适用于任意非等价成本的
预算约束。选择同分布的多个独立源可能仍能降低噪声；max 型代理可能低估这种收益。
这些正是诊断要检查的失败模式。

## 5. 冻结比较和下游方法

比较策略：

| 名称 | 选择规则 |
|---|---|
| all | 使用所有源，作为软加权全源参照 |
| relevance | 按公共排名一致性/标准误独立排序选前 b 个 |
| random | 同一种子下随机选 b 个；一次抽样，不声称积分所有子集的期望 |
| coverage | 上述集合边际增益贪心 |

relevance 复用原服务器级相关性思想，不等同于原 adaptive_censor_aware 的所有权重
处理细节；本轮不是旧 G3 的精确重跑。为隔离选择问题，所有子集统一调用原全源版
fuse_censor_aware_item_context(chosen, q, ...)（在该子集上重算系数）。
不使用第二步表现不稳定的新区间估计器，以免同时改变选择和估计目标。

两种候选模式：

- selected：仅使用所选源并集 C_J，丢弃其他项目；报告实际 C_J 覆盖上界。
- retained：保留已获取全源并集 C_all，但仅用所选源的频率/删失信息评分；这些额外
  项目的出现信息来自已经看过的未选源，不得称为只观察所选源的算法。

新增记录包括：所选 ID、代理效用、实际候选规模、所选候选 Recall、选择损失的真实
Top-k 比例、使用/已获取项目数、选择耗时和融合耗时。真实覆盖仅用于评估。
采集数始终计全部源；不把 used_item_count 当作减少后的通信量。

## 6. 实际诊断范围

experiments/validation/diagnose_adaptive_selection.py：12 个独立新种子、4 条件、2 协议、预算2/3/6。
域128、每源1500、6源、k10、每源发布20；OUE/OLH，不引入 PEM 的额外观察模型。
条件为弱上下文(.25)、强上下文(.75)、误导上下文和同分布源冗余。最后一项把前三个
源分布设为第一个源分布，但用户采样和 LDP 扰动独立，不复制同一份报告。

所有方法共用发布；上下文变体固定源总体和报告随机流。预算6必须与全源预测完全一致，
脚本逐例断言。相同全源参照会在各预算/模式重复记录，不计作独立实验重复。
结果用种子配对 bootstrap 做探索性逐项区间，不以此宣称校正后的普遍显著优势。
预算增加时真实准确率不必单调，也不强行选择表现最好的预算作为本轮结论。

运行：`./.runtime/python/python.exe experiments/validation/diagnose_adaptive_selection.py`（top-k 目录）。
结果在 outputs/adaptive_selection_diagnostic。相同设计重跑会覆盖该诊断结果；不同代码
或配置摘要会拒绝复用该目录。该脚本目前不是断点续跑器。

## 7. 本轮完成的边界

完成的是：定位选择约束、公开集合代理目标与其保证、可执行策略、可达候选诊断、
固定比较与实测结论。没有声称解决最优估计误差选源、自动决定预算、抗恶意攻击，
也没有产生新的用户级隐私采样协议。
后续是否保留硬选源，必须由相对全源软加权的质量/成本证据决定。
