1. 打开程序

  1. 把整个压缩包解压到一个可以读写的目录。不要在压缩包预览窗口直接运行，不要单独移动 runtime 或 application。
  2. 双击 启动程序.cmd。窗口会显示本机网址并尝试打开浏览器；没有自动打开时，复制窗口里的实际网址到浏览器。
  3. 默认尝试端口 8765，忙时自动使用空闲端口；只监听 127.0.0.1。不需要开放公网端口，也不会停止其他程序。
  4. 演示结束，在启动窗口按 Ctrl+C。重新启动会清空演示账本与密钥；需要留存的现场结果请先使用页面的证据导出功能。

核对冻结文件哈希，检查三数据预测、严格与描述性 A8 接口，以及账本副本篡改后的拒答。

运行测试.cmd

使用包内解释器运行回归测试；测试数和结果以当前版本实际输出与验收记录为准。通过不代表真实部署已经安全或预测准确。

2. 按顺序体验五个页面

先选择美团 TRD，再点击首页正常交换。它会固定带入包内功能自检使用的条件：目标商圈10、ε=2、Top-m=40、每源采样上限1000、种子1。这是用于展示一次“检查通过”完整流程的可重放操作条件，不代表总体预测效果。若要展示“降级”，可手动改为商圈3、ε=1、Top-m=20、每源5000、种子20260929，观察来源一致度不足时系统保留结果并说明原因。

  1. 总览：明确输入、角色和防线

    首页默认只保留操作入口；“系统工作流程图”展开后说明用户端、发布者、注册表、账本、网关和审计之间的关系。当前这些角色在同一个进程模拟。点击正常交换只填参数，不自动运行。

  2. 冷启动预测：执行正常摘要交换

    核对上面的参数后点击开始预测。观察扰动、发布、准入、融合事件，以及最后的 Top-10、决策状态、具体原因和离线评价。保存请求快照和本次结果；再用相同种子重放时，决策、榜单和评价应一致，窗口、时间和哈希可以变化。

  3. 攻防实验室：比较两种不同性质的威胁

    回到总览点击投毒对比，或选择“权重劫持（谎报极小方差 + 注入）”，攻击来源数1，再点击发起攻击。它是合法签名的数值投毒，重点看鲁棒融合如何改变影响；没有签名拒收并不表示防线无效。

    然后点击篡改检测，对应“中间人篡改摘要（不重新签名）”。观察 SIGNATURE_INVALID 等真实准入原因。单份摘要拒收与整次请求状态分开解释，不能预设整次一定拒答。

    点击一键全攻击巡检可依次执行十种攻击；种子留空时巡检使用20260929。看每项实际结果与原因，不把十项通过当作普遍鲁棒性证明。

  4. 账本审计：检查原链，再篡改副本

    先观察窗口预算、条目、链头和密钥注册表。已有记录后选择合法序号（例如0），点击执行演练。预期副本触发 REFUSED / LEDGER_CORRUPTED，并单独复核原链条目数、链头及完整性未变。空账本不能演练，先完成一次预测。

  5. 实验中心：阅读已登记的历史证据

    查看隐私效用、投毒、权重劫持、形式化和开销，再看四方法描述性对照及限制。这里读取存档，刷新不是重跑实验。严格入口 NOT_RUN 与描述性入口 AVAILABLE 可以并存，二者不是同一种证据。

“检查通过 / NORMAL”仅表示本次检查达到要求，不表示预测准确或攻击彻底失败。合法签名也不保证发布值真实。评价只用于离线代理任务，目标真值不输入推理。

3. 参数和结果怎么读

字段含义及注意事项
数据集与目标区域目标区域留出作离线评价，其余区域提供摘要；切换数据集会改变类别域和可用源。区域拓扑是示意图。
ε本地差分隐私参数。增大通常意味着较弱隐私噪声，不是准确性保证；要结合数据和具体实验看效用。
Top-m / 每源采样上限每源发布多少类、最多抽多少用户。最终输出 Top-10；采样上限可能大于该源实际可用用户数，以结果为准。
种子单次留空为新的随机运行；固定值用于重放。数值相同不意味着运行ID、窗口、密钥或签名哈希相同。
攻击来源数 / β请求攻击源数与实际源数分别查看。MGA中β是伪造报告数相对每源诚实采样数的比例；实现按round(β×该源诚实采样数)取整生成，实际伪造数以来源记录为准。β不是伪造报告占总报告的比例，也不是所有攻击的共同强度。
攻击目标入榜比例看实际入榜目标数 / 实际攻击目标数。无目标为不适用，缺失为未提供；不能把空值补成0。
Recall@10 / NDCG@10离线目标真值上的召回与排序指标。攻防页“无防御基线”为无防御方差加权；四方法实验中另有简单平均。
过滤 / 准入拒收 / 整次拒答分别发生在发布端、网关和决策层。拒答因候选不足时可能保留部分候选，账本损坏路径应为空榜。

改参数后，页面保留的旧结果应标为上次运行；切页与切数据集不会把迟到结果冒充新请求。刷新网页会清空页面记录，重启服务才会清空服务内存账本。现场证据导出是请求与响应记录，不是第三方认证或统计登记。

7. 常见问题

浏览器没打开 / 旧网址无法访问
保持启动窗口打开，复制其实际网址；端口可能变化。页面重试连接只重试当前连接，不能替代启动服务。
文件哈希检查失败
保留错误名单，重新完整解压原ZIP到新目录。不要删掉检查或改manifest把失败“修成通过”。
复现失败或被中断
查看该会话结果索引与stderr；不要把上次成功结果当成本次结果。再次运行会创建新会话，不覆盖失败记录。
图表缺中文
绘图优先使用系统微软雅黑/黑体等可用字体。工具不复制系统商业字体；记录实际字体环境，避免把字体差异当作统计差异。
页面看到了结果，为什么不是新的实验结论
现场运行是单次示例，实验中心是存档查看，快速核验是小样本流程检查，完整A8入口是旧种子复现。各自支持的结论不同。

8. 保持这些边界

主线是多源 LDP 摘要的抗投毒可信交换。OLH、Ed25519 和 ProVerif 等是已有组件；作品贡献与第三方基础组件分别说明。原始研究代码称“团队原始研究代码”，来源与许可按文件记录。

同进程角色模拟，无登录，账本与密钥驻留内存；哈希链不能保证抵抗宿主整链重写或分叉。跨窗口隐私预算解释依赖部署假设，账本不能验证用户集合是否不相交。

定理1限制无诚实支持新品类的注入，不保证已有品类名次稳定。定理2须满足无上下文路径、每源仅一份摘要、n≥3且f<(n−1)/2、有限正方差、非负截尾下限0及κ≥1等完整前提。若诚实源未封顶权重满足0<w≤u≤W，则恶意权重份额α≤fκW/((n−f)w+fκW)。仅在n=10、f=1、κ=2且W=w的例子中，上界为2/11≈0.1818（约0.182）；诚实源权重只是相近而非相等时，须代入真实W/w，不能把0.18写成普遍上界。具体条件以报告与界面完整说明为准。

无攻击时不主张比简单平均更准；不利结果与拒答代价应一并阅读。程序测试通过、模型验证通过、界面“检查通过”都不能扩展为预测准确或现实部署无风险。最终实体第二台电脑兼容性以实际验收记录为准。
