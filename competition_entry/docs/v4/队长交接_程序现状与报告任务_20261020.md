### 1.2 五个页面

1. **总览**：数据交换关系、三条防线、五个入口（正常交换、投毒对比、篡改检测、账本审计、实验结果）。

3. **攻防实验室**：单次攻击（MGA、compromised、hijack、demote、negative、tamper、replay、impostor、equivocation、budget_burn）+ 一键全攻击巡检；协议类显示“准入/拦截”对比，投毒类显示 AS/Recall/NDCG，账本类显示登记拒绝。
4. **账本审计**：摘要 → 账本条目 → 预算 → 网关审计记录 → 副本篡改演练；演练结果会写入审计记录（类型“演练”），并显示被改条目的主体、窗口、ε。

### 1.3 处理链路（报告 2.4/2.5 的事实基础）

1. **用户端**：类别 → OLH 扰动 → 上报哈希种子与桶值。
2. **发布端**：按用户级报告做共同支持筛查 → 频率/方差估计 → 生成 Top-m 摘要。
3. **签名发布**：`ReleaseEnvelope` 封装发布源、窗口、类别域、机制/哈希族、ε、用户数、Top-m 条目；`seal` 对规范化 JSON 签名；登记账本。
4. **网关**：先验账本链；逐份检查签名/角色/窗口/类别域/ε/用户数/登记存在性/摘要一致性；同源多份有效摘要全部拒收。
5. **融合**：多源支持门槛、留一截尾、权重封顶、方差加权。
6. **决策**：NORMAL / DEGRADED / REFUSED + 原因码；离线 Recall/NDCG 另算。

### 1.5 签名与账本（2.5.4/2.6.3 的事实基础）

- 签名：**Ed25519**（`keys.py`，引用 RFC 8032[11]）。
- 信封：`ReleaseEnvelope`，签名覆盖规范化 JSON（排序键、紧凑分隔符、UTF-8）；`signature` 自身不入被签正文；`digest` 同时绑定正文和签名。
- 密钥注册表：`key_id → (公钥, 主体, 角色)`；登记时先核对签名与 `source` 角色。
- 账本：按“源 + 窗口”累计预算；条目含 `prev_hash`、`entry_hash`；登记前验签、拒绝重复编号/nonce、检查正整数用户数和正有限 ε；链断裂 → `REFUSED` + `LEDGER_CORRUPTED`。
- 协议异常：重放（旧窗口/重复）、冒充（未注册密钥）、同源多摘要（`EQUIVOCATION`）、预算耗尽（`BUDGET_*`）。
- 账本演练：复制账本改一条 ε，重算链在首断点失败；原账本复核不变；演练只动副本。

### 1.6 ProVerif（2.6.3 的事实基础）

- 主模型 `privedge_release.pv`：Q1–Q5 全部 `holds=true`。
- 可达性：S1/S2 的“不可达”查询为 `false`，即接受事件可达。
- 四个负对照分别按预期破坏：nc1 窗口未签名（Q1/Q2）、nc2 角色不绑定（Q3）、nc3 网关跳过账本（Q2）、nc4 账本跳过签名（Q5）。
- 边界：模型不覆盖预算数值、输入合法性、同源多摘要拒收、宿主重写整条链、统计防御和性能；不能把 Q1–Q5 当代码安全或 LDP 数值证明。

### 1.7 后端接口（2.8 的事实基础）

### 1.9 已知边界（写报告不要越过）

- 无攻击时**不宣称优于简单平均**；部分鲁棒基线在个别切片更好。
- 两源合谋仍有残余：ε=1 时两源权重劫持 AS 可到 0.93–1.00；Massive 双源约 0.8476。

## 5. 用 GPT 辅助修改的正确方式

### 5.1 每次只喂一节

1. 本节正文（从 docx 复制）；
2. 本文档第 1–4 节（程序事实、参数、数字）；
