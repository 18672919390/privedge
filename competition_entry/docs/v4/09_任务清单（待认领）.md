## 二、怎么选任务

| 如果你…… | 可以优先看 |
|---|---|
| 熟悉 Python / NumPy，懂一些差分隐私、统计或推荐 | A 类（算法与实验） |
| 熟悉团队原始研究代码（融合算法、OLH 实现） | A 类上手最快；也适合复核 08 号改动记录 |
| 学过密码学、安全协议，愿意读证明 | B 类（安全与形式化） |
| 会前端 / 后端开发，或会录屏剪辑 | C 类（系统、演示与复现） |
| 文字能力好、细心，愿意统筹 | D 类（报告与材料） |

工作量按"人日"估计：1 人日约等于一个人专心工作一天。**必做**合计约 25 人日，**可选**约 8 人日（另有入围后才需要的 D9）。四个人三周足够，但带硬截止的任务要先做。

**每个人都要做**：读完 07（约 40 分钟）→ 在自己电脑上把项目跑起来（按《从这里开始》）→ 做一个上手任务（A1、B1、C1 任选）→ 参加两轮模拟答辩。

## 四、做任务时的规则（摘自 07 第 11 节）

1. 报告里的每个数字都要能在 `02_实验证据登记` 找到编号；新实验先写预注册再运行，结果不好也照写。
2. 不修改 `privedge/runs/` 下已有的运行目录和 `review/` 下的原始研究代码；新运行进新的运行目录。
3. 改了代码要跑一遍 `run_tests.bat`，并在 `08` 第 7 节追加一行记录。
4. 发现和文档或报告冲突的地方，先在群里说，不直接改结论。
5. 材料只在队内流转，不上传到公开网站。
