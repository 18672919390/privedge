## 1 作品定位

**工作名称**：PrivEdge——面向新区域开站选品的多源隐私保护可信 Top-K 需求情报系统

**应用场景**：配送企业要在新区域开设前置仓或配送站（低空无人机配送站是其中一种落地形式），开站前必须确定首批备货的 Top-10 品类。新区域没有历史订单，只能借助已运营区域的需求信息，但个人订单受隐私法规保护，不能共享。

**一句话**：各已运营区域只发布经本地差分隐私（LDP）保护、带签名和预算记账的 Top-m 品类摘要；新区域在拿不到任何一条原始订单、也无法核实任何一个用户的前提下，得到可信的 Top-k 品类清单，证据不足时拒答。

**核心竞争力**：不是"预测更准"（三套真实数据上，团队原始融合相对简单平均没有稳定优势），而是"在隐私保护下仍然可信"。LDP 的数据对汇聚方不可验证，伪造报告混在噪声里无法分辨；不设防时（ε=1，SECURITY_V2），1 个源混入 5% 伪造用户，就能以 0.26–0.59 的概率把 3 个冷门品类挤进新区域 Top-10（10% 时为 0.90–1.00）。PrivEdge 把这两种情况都降到 ≤0.02，而无攻击时精度几乎不损失。持有合法密钥、谎报极小方差的被攻破发布者，能让只做截尾的系统 NDCG 下降 0.44–0.66（SECURITY_V3）；权重封顶把差距压到 0.09 以内（SECURITY_V4 新种子复验）。关键防线都有可证明的界（定理 1、2）和形式化验证（ProVerif）。

**为什么属于网络安全作品**：保护的是个人消费行为（可推断住址、健康、经济状况等敏感属性）；防御对象是不可信汇聚方、伪造用户、被攻破的发布者，以及摘要的篡改与重放。Top-k 选品是被保护的业务，安全机制是作品主体。

**与 SkyGuard 的区别**：SkyGuard 保护无人机**飞行轨迹**、解决**两机碰撞检测**，技术是 PSI/OKVS/DDH；PrivEdge 保护**地面用户行为**、解决**多方统计共享与新区冷启动**，技术是 LDP、截断感知融合、抗投毒聚合、签名账本。两者场景相邻、技术不重叠。

## 2 问题模型

- 源服务器 \(S_1,\dots,S_n\)：已运营区域（州/城市×时间窗）。每个用户 \(u\) 在窗口内贡献一个类别值 \(x_u\in\mathcal{D}\)，\(|\mathcal{D}|=d\)。
- 用户端：在本地用 OLH 扰动 \(x_u\) 后上报，原始值不离开设备。
- 源端发布：对上报做频率估计，只发布估计值最高的 Top-m 类别、估计频率、方差、用户数、机制参数，封装为签名的 `ReleaseEnvelope`。
- 目标服务器 \(T\)：新开站区域，没有私有行为；只能读取各源的 `ReleaseEnvelope`。可选输入：自身独立的公开上下文 \(c_T\)（POI/设施计数，时间早于目标窗口），但只作附带说明，不作为效用来源（两套数据的 Gate D 均未通过）。
- 输出：Top-k 类别、置信度、来源贡献、隐私预算状态和三态标记（正常/降级/拒答）。
- 离线评估器：唯一可以读取目标真值的模块，只在实验中计算 Recall@k、NDCG@k。

## 3 安全模型

| 角色 | 假设 | 能力 | 目标 |
|---|---|---|---|
| 汇聚方（源服务器） | 诚实但好奇 | 看到本区全部 LDP 报告 | 推断单个用户的类别 |
| 外部窃听者 | 被动 | 监听发布通道 | 获得摘要或推断用户 |
| 伪造用户 | 主动 | 向某区域注入伪造 LDP 报告（最大增益攻击 MGA） | 把指定类别推进目标 Top-k，误导新区域备货 |
| 被攻破的发布者（f 个） | 主动，持有合法签名密钥 | 发布任意摘要：抬高目标品类、谎报极小方差劫持融合权重、发布负频率压低真实热门、同一窗口提交多份不同摘要 | 注入品类或破坏排序 |
| 中间人 / 第三方 | 主动（Dolev-Yao） | 篡改、重放旧窗口摘要、用未注册密钥冒充数据源、以他人名义向账本登记以耗尽其预算 | 让目标使用过期或伪造信息；拒绝服务 |
| 目标服务器 | 诚实但好奇 | 看到全部摘要 | 反推源区个体 |

不在范围内：用户是否参与本身的隐私（参与隐私）、公开上下文本身的隐私、最终 Top-k 与外部知识结合的群体推断。报告中如实写明。

## 4 设计目标

1. **隐私**：每个用户在每个窗口满足 ε-LDP；重复发布按顺序组合记账，超预算拒绝发布。
2. **完整性与真实性**：摘要与上下文必须带发布者签名、域哈希、窗口号和新鲜度字段；任何篡改、重放、域错配可被检测。
3. **鲁棒性**：在一定比例伪造用户或恶意源下，目标 Top-k 的攻击成功率和效用损失有界，并可检测。
4. **效用**：ε≥2 时仅凭 LDP 摘要恢复的目标 Top-10 接近非隐私源平均水平（UTILITY_V1：TRD 在 ε=2 时 Recall@10 为 0.835，非隐私参照为 0.873）；ε=1 时 Recall 低约 0.11。开启全部防御（含权重封顶）后，无攻击时 NDCG 损失 ≤ 0.02，权重封顶本身在效用网格上零变化。公开上下文只在通过验证后使用，且不宣称它带来提升（Massive 与 Olist 的 Gate D 均未通过）。以预注册口径报告，不利结果同样报告。
5. **可用性**：证据不足时降级到公开基线或拒答，并给出原因；每次输出可审计、可复现。
6. **效率**：用户端扰动与通信开销适合移动端/边缘设备；目标端推理毫秒级。

## 6 方案原理与实现要点

### 6.1 LDP 发布
- OLH：用户随机选哈希种子，把类别哈希到 \(g=\lfloor e^\varepsilon\rfloor+1\) 个桶后做 GRR 扰动；源端无偏估计频率，方差 \(\mathrm{Var}=\frac{4e^\varepsilon}{n(e^\varepsilon-1)^2}\)（近似）。
- 只发布 Top-m，同时发布方差与"未发布项上界"，供目标端做截断感知估计。

### 6.2 签名发布契约与账本
- `ReleaseEnvelope` 字段：`release_id, source_id, window_id, domain_hash, mechanism, mechanism_version, epsilon, n_users, top_m, items[{category, freq, var}], tail_bound, context_ref, created_at, nonce, prev_hash, signature`。
- 规范化 JSON（键排序、UTF-8、无空白）后用 Ed25519 签名；账本为哈希链，每条记录包含前一条哈希，任何删改会断链。
- 预算台账：同一用户群体在同一窗口的多次发布按顺序组合累加 ε；超过策略上限时发布器拒绝签名，网关拒绝接收。
- 附带：若使用公开上下文，同样封装为签名 `ContextEnvelope`（区域、角色、快照时刻、域哈希）并入账；未通过验证即不用。CONTEXT_V1 已验证错配/篡改 100% 被拦截，报告中作为一段附带说明，不单列创新点。

### 6.3 截断摘要融合（团队原始算法，基础能力）
沿用团队原始研究代码中的 `censor_aware`、`variance_weighted` 等方法，并迁入正式包；正式包不修改其数学逻辑，只补接口和签名输入。它在 ε≥2 时恢复的 Top-10 接近非隐私源平均，但不作为创新点。

### 6.4 两层抗投毒聚合（主创新）
- 威胁 1（伪造用户）：按最大增益攻击（MGA）构造 OLH 报告，把冷门品类推进 Top-k。
- 威胁 2（被攻破的合法发布者）：持有合法签名密钥，直接抬高目标品类的发布频率，发布端检测对它无效。
- 发布端：利用 OLH 已知噪声结构计算类别对的联合支持超额量，贪心扩展成可疑项集（保留比例 0.7），剔除支持全部成员的报告；无攻击时从不触发。
- 网关端：留一共识截尾（尺度取其他源方差的中位数，不信任被检源自报的方差；下限 0，防止用负频率压低真实热门），并要求候选品类至少获得 t=2 个源支持。
- 威胁 3（权重劫持，SECURITY_V3 发现）：被攻破发布者谎报极小方差，在方差加权中独占权重。防御：权重封顶，每个源的权重不超过其余源权重中位数的 κ=2 倍。按预注册规则，V3 中未采用；SECURITY_V4 在新种子上确认后才成为默认。
- 可证明的界：定理 1（支持规则）和定理 2（有界影响），见 `03_容错定理与证明.md`。
- 源异常分数只作告警，不改变输出（异质区域上误报严重）。
- 评价：攻击成功率、伪造报告移除率、诚实报告误删率、无攻击时的效用损失，随 β、恶意源数、ε 变化（SECURITY_V2、V3、V4 已完成）。

### 6.5 三态输出（功能，不单列创新点）
- **拒答**：通过网关的源少于 3 个，或满足 t=2 支持的候选品类不足 k 个。单份摘要签名失败、重放、域错配、预算超限，只拒收该份摘要，不直接拒答整个请求。
- **降级**：源间 Top-m 平均 Jaccard 低于 0.2，或上下文未通过验证；输出仍给出，但标记原因码。
- **正常**：其余情况，输出 Top-k、每个品类的支持源数、来源与账本摘要值。

## 7 安全性分析计划

1. OLH 满足 ε-LDP 的证明；Top-m 截断与融合属于后处理，不增加隐私损失。
2. 同一窗口多次发布的顺序组合与不同窗口的并行组合；预算台账的正确性论证。
3. 签名与哈希链：基于 Ed25519 的不可伪造性论证完整性与来源真实性。
4. **ProVerif 形式化验证（已完成，FORMAL_V1）**：Q1 认证、完整性与窗口绑定；Q2 账本绑定（对被攻破源也成立）；Q5 不可代扣预算；Q3 上下文角色隔离；Q4 原始数据保密，全部成立。4 个负对照各去掉一项检查，都按预期被攻破，其中 nc4 对应设计审查中发现的真实缺陷（账本登记不验签）。
5. **容错定理（已完成）**：定理 1，f<t 时未被任何诚实源发布的品类不能进入输出，界是紧的（f=t=2 时 300/300 次注入成功）；定理 2，诚实多数下，任一品类分数受被攻破源影响的幅度被其权重份额 α 界定。
6. 抗投毒的经验界：不同 β、恶意源数、ε 下攻击成功率的实测结果（SECURITY_V2–V4）。

## 8 前端与后端

- 后端：Python FastAPI + WebSocket，读取带运行 ID 的真实实验产物，也可实时执行发布—验证—预测流程。
- 前端（已实现）：Vite + React + TypeScript + ECharts，构建后由后端同端口托管，可离线运行。
  - **总览**：架构流程、核心指标（从登记的运行目录读取）、定理摘要与局限。
  - **冷启动预测**：选择新开站区域、ε、Top-m、每区域用户数，后端通过 WebSocket 逐步推送真实执行事件（本地扰动、签名发布、账本登记、网关接受或拒收、决策），拓扑图实时着色。结果显示 Top-10、支持源数、三态与原因码，离线评估单独标注。TRD 商圈没有公开坐标，所以拓扑图是示意图，不画地理地图。
  - **攻防实验室**：10 种攻击（MGA、被攻破注入、权重劫持、劫持 + 扣热门、负频率、篡改、重放、同源多摘要、冒充、代扣预算），每种标注对应防线。与无防御基线并排比较。一键巡检在同一目标、同一种子下依次执行全部攻击。
  - **账本审计**：哈希链状态、链头、预算消耗、密钥注册表、网关审计记录；篡改演练在账本副本上修改一条记录，验证能精确定位断点。
  - **实验中心**：隐私—效用曲线、Top-m 敏感性、SECURITY_V2 攻防、SECURITY_V4 权重劫持、ProVerif 结果与负对照、开销，每张图注明运行目录；可在线阅读全部预注册文档。
- 断开后端时前端只显示"后端未连接"，不显示任何伪造数值。

## 10 创新点（候选，最终以实验证据为准）

基础能力（不作为创新点）：团队原始的多源 Top-m 截断摘要融合算法。三套真实数据显示，ε≥2 时它能恢复接近非隐私源平均的 Top-10（ε=1 时 Recall 低约 0.11，Olist 除外）；但截断感知与上下文类方法相对简单平均没有稳定优势，所以只作为系统的基础能力。

v4.1 定稿为三个创新点（2026-09-29 更新：定理与形式化验证已完成）。

**创新点一：面向 LDP 摘要的两层抗投毒聚合（含自适应攻击与权重封顶）**
发布端利用 OLH 已知噪声结构做联合支持项集检测，剔除伪造用户；网关端做留一共识截尾（下限 0）、多源支持规则 t=2 和权重封顶 κ=2，限制持有合法密钥的被攻破发布者。证据：
- SECURITY_V2（三套数据）：伪造比例 ≥5% 时，攻击成功率由最高 1.0 降到 ≤0.02，伪造报告移除率 ≥98%。被攻击源内诚实报告误删率约 1.6%（ε=1）/ 0.2%（ε=2），无攻击时过滤器从不触发。1 个被攻破发布者：Massive 上由 0.69–0.75 降到 0.04–0.22。D0 攻击成功率 ≥0.1 的 26 个单元中，24 个被显著压低。无攻击时 NDCG 变化在 [−0.0012, +0.0198]。
- SECURITY_V3 → V4：主动构造了 V2 未覆盖的自适应攻击，即谎报极小方差的权重劫持；只有截尾时，劫持 + 扣热门使 NDCG 下降 0.44–0.66。权重封顶按预注册在 V3 中未被采用（注入抑制未全部显著）；在新种子上做确认性复验（V4）后才采用：不回退 14/14 ×3 套数据，单源劫持 / 降级下与无攻击的差距 ≤0.09，效用网格 1,920 行逐行不变。
- 已知上限：f ≥ t（2 个发布者合谋）时注入不能阻止（ε=1 时 Massive 1.0 → 0.98；2 源劫持 0.93–1.00），只能靠 t=3 换取（无攻击 NDCG 损失 0.039）。

**创新点二：多源支持规则与有界影响的可证明容错界**
- 定理 1：f 个被攻破发布者不论发布什么，输出中每个品类都至少被 t−f 个诚实区域发布过；f<t 时，未被任何诚实源发布的品类不能进入输出。界是紧的：f=t=2 时构造的攻击 300/300 次注入成功。400 次随机对抗的性质测试（截尾开或关）全部通过。
- 定理 2：诚实多数 f<(n+1)/2 下，截尾 + 下限 0 + 权重封顶使任一品类分数满足 \((1-\alpha)S_i^H \le S_i \le (1-\alpha)S_i^H+\alpha U_i\)，其中 \(\alpha\le f\kappa W/((n-f)w+f\kappa W)\)。这把"权重封顶为什么有效"和"负频率为什么必须截到 0"变成了可检验的结论。
- 定理推导直接发现了两个实现缺陷（负频率删除、同源多摘要突破 f 计数），均已修复并加测试。

**创新点三：可审计的隐私预算账本与形式化验证的发布协议**
Ed25519 签名契约，签名覆盖窗口号，以 (主体, 角色) 绑定密钥；账本为仅追加哈希链，登记前验签，预算按窗口顺序组合。网关核对账本中的摘要值，同一窗口一源多摘要全部拒收。ProVerif 2.05（Dolev-Yao）下 Q1 认证、完整性与窗口绑定，Q2 账本绑定（对被攻破源也成立），Q3 上下文角色隔离，Q4 原始数据保密，Q5 不可代扣预算，全部成立。4 个负对照各去掉一项检查，均按预期被攻破，其中 nc4 复现了设计审查中发现的真实缺陷：修复前账本登记不验签，任何人都能以他人名义耗尽其预算。

**附带说明与功能（不单列创新点）**：上下文溯源绑定与三态输出。公开上下文按区域、角色、类别域、因果时间签名并登记账本，未通过验证就降级为仅用摘要，证据不足时拒答。证据（CONTEXT_V1）：错配和篡改的上下文 100% 被拦截；未签名篡改的攻击成功率由 0.14–0.25 降到 0–0.03；只剩 2 个源时 100% 拒答。残余风险：上下文密钥泄露时攻击成功率只能降低约一半。
